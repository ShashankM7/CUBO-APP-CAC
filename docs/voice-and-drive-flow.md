# Web voice and drive flow

- `main` and `shashank-new-ui` share this implementation when the new UI is published. `shashank-expo` is intentionally separate.
- Map → Start drive requires a route and GPS, then starts directly. It no longer opens LiveDrive's camera-check/calibration flow. Home and Account still expose calibration. The drive camera loads the saved baseline; missing calibration, frames or GPS must never produce a valid attention score. Recalibrate when moving the mount; browser permission prompts are controlled by the browser.
- Child 2 uses the existing MapLibre/OpenFreeMap renderer, not a blank schematic. It is a non-interactive street-map preview with fictional Raleigh coordinates, simulated movement and attribution. It does not request the viewer's GPS. The renderer is unmounted when the profile loses focus.
- Voice Assist recognizes brief silence requests (stop, shut up, stop talking, stop reading, be quiet) without a wake phrase. These silence playback without disabling the conversation or confirming a report. Turning voice off still asks for confirmation.
- During speech, the interruption recognizer accepts only silence requests, never hazard commands or confirmations. iOS is no longer categorically excluded, but capture failures disable interruption for that voice instance. Regular conversation capture can still retry once. Browser support is best-effort: the AI toggle / Stop read-aloud button remains the reliable fallback.
- Listen asks separately before opening speech recognition and offers Listen without microphone. Consent is session/account scoped. Completion, cancellation, leaving the screen and backgrounding release audio resources. No raw audio is saved by CUBO; browser speech providers may process it online.
- Additional deterministic phrasing covers vehicle selection, numbered children, route/destination/ETA questions, accident/obstacle reports, and go ahead / scratch that confirmations. Negated reports and reroutes cannot execute actions. These additions do not load an AI model or add dependencies. Map tile traffic and browser speech processing still depend on network/device conditions.

Validation: TypeScript, production export and automated tests; Chrome rendered the real demo streets and answered a natural vehicle query with saved data. Actual iPhone simultaneous speech/recognition, moving-GPS navigation and camera monitoring still need physical-device testing while safely parked/passenger-assisted.
